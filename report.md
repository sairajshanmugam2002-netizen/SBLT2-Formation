## 3. "Logged Rework / Rejection Records" Grid — Source Data

The grid at the bottom of the page (`#Grid`) displays existing records. Here is exactly where the data originates:

### Flow Diagram
```
[SQL Server: Formation_Rework_Rejection]
                    │
                    ▼
[Stored Procedure: pr_fetch_Formation_Rework_Rejection_List]
                    │
                    ▼
[C# Controller: TransactionController.pr_fetch_Formation_Rework_Rejection_List()]
                    │
                    ▼
[JSON Response via AJAX: ../../Transaction/pr_fetch_Formation_Rework_Rejection_List]
                    │
                    ▼
[Frontend UI: jqxGrid (#Grid)]
```

### Stored Procedure Definition
```sql
CREATE PROCEDURE [dbo].[pr_fetch_Formation_Rework_Rejection_List]
AS
BEGIN
    SET NOCOUNT ON;
    SELECT 
        ROW_NUMBER() OVER (ORDER BY FRR_ID DESC) AS SNo,
        FRR_ID,
        ISNULL(FRR_QRCode, '-') AS FRR_QRCode,
        ISNULL(FRR_BatteryType, '-') AS FRR_BatteryType,
        ISNULL(FRR_CKTNo, '-') AS FRR_CKTNo,
        ISNULL(FRR_Type_Name, '-') AS FRR_Type_Name,
        ISNULL(FRR_Reason, '-') AS FRR_Reason,
        ISNULL(FRR_Employee_Name, '-') AS FRR_Employee_Name,
        ISNULL(FRR_Created_By, '-') AS FRR_Created_By,
        CONVERT(VARCHAR(19), FRR_Created_Date, 120) AS FRR_Created_Date
    FROM Formation_Rework_Rejection
    WHERE FRR_Status = 'A'
    ORDER BY FRR_ID DESC;
END
```

- **Implemented Fix:**
  - Removed the visual field column from the grid layout.

## 6. Identified Issues & Recommendations

During the code and database audit, the following issues were discovered for your attention:

### 1. Hardcoded Formation ID (`FRR_Formation_ID = 68`)
- **Location:** [TransactionController.cs line 152](file:///d:/office/MVRLA_Formation/MVRLA_Formation/SBLT2/Controllers/TransactionController.cs#L152)
- **Code:** `cmd.Parameters.AddWithValue("@FRR_Formation_ID", 68);`
- **Issue:** Every single rework or rejection record is saved with `FRR_Formation_ID = 68`. If the factory runs different batches or tanks, all records will still point to batch ID 68.
- **Recommendation:** Retrieve the active Formation ID from the user's active batch session or pass it dynamically from the scanner lookup.

### 2. Lack of Duplicate Scan Protection
- **Location:** Stored Procedure `pr_insert_Formation_Rework_Rejection`
- **Issue:** There is no uniqueness check on `FRR_QRCode` + `FRR_Status`. If an operator scans the same battery twice or double-clicks "Save Record", two identical rejection/rework rows with two separate `FRR_ID` values will be inserted.
- **Recommendation:** Add a short debounce on the Save button and consider checking in SQL if the barcode has already been rejected in the current active shift.

### 3. Reason Dropdown Dependency on `Reference_Group_Value`
- **Location:** `TransactionController.pr_fetch_Rework_Rejection_Reasons`
- **Issue:** Reasons are fetched by filtering `RGV_iRG_ID = @Type_ID`. If reference group IDs in the database are modified or re-seeded, reasons may not load.
- **Recommendation:** Maintain a foreign key or code-based mapping (`RG_vCode = 'REWORK'`) rather than relying purely on integer IDs.
